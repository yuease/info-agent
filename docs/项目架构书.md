# 信息筛选助手项目架构书

版本：v2.0 实现版；日期：2026-10-24。

本书描述最终源码；原 v1.0 为目标设计，实施前仅有 RSS、一次筛选、Markdown 输出和 5 项测试。本次使用现有 Python 3.11、LangGraph 和依赖，不重建环境。当前 61 项离线测试通过，未调用真实付费模型。

## 1. 产品边界

仅从用户关键词对应 RSS 获取信息，不扩大关键词或相邻主题。推荐输入只含 ID、来源 URL、标题、清理后简介、作者、发布时间、RSS 时长与标签。模板播放量、收藏量、评论量、弹幕量不参与推荐。不获取字幕、下载音视频或转写。不实现主题／作者黑名单。用户明确兴趣优先于自动推测。

每轮一次逻辑模型筛选；SDK 网络重试单独计数，不增加模型审稿或纠错调用。探索来自同一短名单、遵守明确兴趣与硬约束、不使用自动学习加减分。默认 K≥5 时约 80/20，K<5 不强制探索。不足时少推荐。

反馈为有用、没用、暂时不想看；可选原因、可撤销、不区分是否观看。无反馈是未知。反馈后本地自动学习，无逐条规则确认，无新增后台进程。

## 2. 模块与执行接口

- `main.py`：编辑器点击运行，继续调用 `main(["--show"])`。
- `__main__.py`：`python -m info_agent`。
- `cli.py`：旧参数兼容及 feedback/preferences/recover/backup/import-legacy 子命令。
- `schemas.py`：统一 Profile/Learning/Article/Choice/Selection 校验。
- `rss.py`：原有 HTTP 采集与身份归一、模板清理、时长标签提取。
- `workflow.py`：LangGraph 装配、prepare、公平截取与运行协调。
- `ranking.py`：短名单校验、有界排序、探索预留与常规补位。
- `preferences.py`：证据归因、上海日期聚合、衰减、快照重算及失败回退。
- `storage.py`：SQLite、幂等事件、事务、原子文件导出、进程中断恢复及备份。
- `rendering.py`：原始来源回填及 Markdown 转义。
- `maintenance.py`：显式导入旧 JSON。
- `metrics.py`：上下文隔离的 HTTP 尝试计数。
- `config.py` / `llm.py`：沿用原模型设置与工厂；同步 HTTP 请求 hook 用于统计 SDK 重试。

`build_briefing(profile, model=None, fetcher=fetch_feed, preview=False, store=None, clock=local_now)` 返回可 `.invoke({})` 的 LangGraph。Profile 在构图时统一校验，CLI 与 Python 接口一致。默认持久化本地 SQLite；测试必须注入临时 Store，避免污染正式历史。clock 返回有时区的 datetime；默认上海时间。测试注入模型沿用原 `with_structured_output(Selection).invoke(prompt)` 协议，生产模型增加 include_raw 获取用量，无新增请求。

为减少为拆分而拆分，图简化为 `START → run → END`，run 内部阶段顺序是 collect/prepare/preferences/select/persist；失败阶段单独记录。未实现 checkpoint 恢复模型执行，失败后新运行仍是新一轮。

## 3. 配置

模型连接及凭据继续在现有 `.env`，本次未读取或改写。用户兴趣继续使用现有 `briefing_profile.json`，完整示例在 `briefing_profile.example.json`。旧四字段格式兼容；未知字段、非法 URL、空关键词或超限参数被拒绝。

策略默认值集中在 schemas.py，可由 profile 覆盖：候选 60（最多 200）、推荐 5（1–10）、关键词 1–5、探索比例 .2、推荐冷却 14 天、later 冷却 3 天。可选硬时长上限，缺失时长在设置上限时排除，否则保留。

learning 默认：启用、半衰期 60 天、总评分调整上限 5、排名最多移动 1、激活至少 3 视频和 3 日期、净证据阈值 1.5、一致性 .7、日净贡献上限 1、最多归因标签 5、时长分桶边界 [300,1200,3600] 秒。评分及移动上限允许调低，不允许突破产品的 5 分／1 位护栏。分桶为 ≤300、301–1200、1201–3600、>3600。

profile_id、排序后的关键词、明确兴趣、硬时长上限与时长分桶规范化后产生 SHA256 context。不同 context 隔离推荐冷却、反馈与偏好。推荐数等展示策略变化不重置学习。

## 4. 数据处理

沿用 RSS XML 根类型、DTD 拒绝、HTTP 协议检查、请求超时 40 秒、响应 2 MiB 限制及本机代理绕过。采集串行，不重试 RSS，不额外请求视频页面。

Article 在原字段上增加 duration_seconds、tags、source_ids、matched_keywords、published_at、fetched_at、parse_warnings。pubDate 转 UTC；异常不制造时间。Length 从模板头部提取 MM:SS 或 HH:MM:SS；MM 可超过 59，秒和 HH 格式分钟须合法；0、异常与缺失为 null。category 清理、casefold、去重，最多 20。简介最多 1200 字符。

仅删除模板头部完整统计行以及尾部 Match By、iframe，不全局删除“评论”“收藏”等正文词。样本 `docs/rsshub-deploy/cursor-test.xml` 的 20 条有时长和标签，作为离线回归证据，不保证未来 RSS 总有字段。未知模板可能需要维护解析器。

身份使用原链接／视频编号哈希，并利用 RSS iframe 已有 AV/BV 对应关系登记别名。冲突不猜测合并，记录警告。不额外访问 B 站转换编号。跨词重复合并 matched_keywords。历史／硬时长过滤后按各词发布时间轮流取唯一候选，不偏向前置关键词。

采集去重全集立即写入 candidates 表及 candidates.json，prepare 后实际模型输入另存 run.json 的 articles。这样过滤原因和原候选均可排查，模型失败也不丢输入。

## 5. 单次筛选与最终排序

一次模型短名单上限是 min(候选数, 2K+E)，E 为探索目标。Choice 包含 id、summary、reason、action、base_score、eligible_regular、eligible_explore、exploration_reason。分数 0–100；探索资格须有依据。旧 Python 调用 Choice 的新增字段有保守默认值（50 分、常规可选、探索关闭）。模型不得返回标题／来源字段；未知 ID、重复、超量、非法分数或结构一律失败，无纠错循环。

提示词取消硬编码“适合初学者”，以用户实际兴趣为准。输入来源指令不执行；不声称看过视频或核实质量，不推断热度或复述营销承诺为事实。

常规短名单按基础分、ID 稳定排序；标签与实际时长特征的激活权重总和截断到 ±max_score_adjustment。只执行互不重叠的相邻逆序交换，保证每条相对常规基础排序最多移动一位。保存 base_position、adjusted_position、adjustment 和 final_score 以审计。该上限约束学习引起的常规重排，不约束探索名额的插入。

E 在 K≥5 时为 floor(K×ratio+.5)，小 K 为 0。先预留合格探索，再取剩余常规；去重，探索不足由常规补足。探索按基础分优先，分数相同再按新增标签、作者差异及 ID 决定，adjustment 恒为 0。无合适内容可为空。

来源、标题、作者与时间取原候选，模型只提供摘要／理由／动作。Markdown 输出转义文本，不把模型虚构来源写入报告。

## 6. 持久化与恢复

标准库 sqlite3，外键、WAL、5 秒锁等待、短事务，user_version=1。当前表：

- runs：ID、context、创建时刻、状态、JSON 运行快照。
- candidates：run+video 唯一，保存规范化采集信息。
- aliases：别名唯一映射，冲突不覆盖。
- recommendations：run+video 唯一，ID 为 run_id:position，保存当时来源和评分快照。
- feedback_events：追加事件、顺序号、目标事件、可选唯一幂等键及请求内容。
- preference_snapshots：context、版本、时间、权重；旧版本不删除。
- preference_heads：context 当前版本及人工恢复固定标记。
- preference_evidence：版本、特征、事件引用、视频、日期及贡献明细。

实现调整：不单设 videos 当前元数据表，候选与推荐快照已满足当前查询；不引入迁移框架、任务队列或新服务。单机规模下保留完整重算便于撤销和审计。

run 状态为 started/collected/completed/empty/preview/failed；selected 只保留为 selection_draft 数据，不另设可恢复执行状态。collect 之后先持久化候选。正式发布时将完整简报正文和 recommendations 一次事务提交，再导出原子替换文件。

这取代原方案“先文件后数据库并猜测补登记”：SQLite 是事实来源，JSON/Markdown 是可再生副本。已提交正式推荐在导出中断后仍计历史，recover 只重导出，不重复登记。未提交的轮次绝不由文件猜测为正式成功。进程已退出的 started/collected 转失败；活跃 PID 跳过（极少数 PID 重用可能延迟判定，可人工核查）。临时文件不会被当成正式产物；恢复不主动删除孤立临时文件。

预览不登记 recommendations、不给反馈对象。失败不占推荐历史。empty 可输出无内容说明，不产生推荐。无候选零模型请求；全来源失败记录 failed，部分失败保留明确提示。

run.json 记录提示词版本、偏好版本、配置、采集失败、计数、短名单与最终选择、常规／探索目标及实际数量、耗时、模型名称、token 和重试。生产同步 SDK httpx 请求 hook 计 HTTP 尝试，重试为 max(0, attempts−1)。token 不可用存 null；进程硬中断导致未完成记录的 HTTP 指标为 null，不冒充零消耗。测试模型自行模拟 transport hook。

## 7. 反馈及本地学习

终端 feedback 可交互或按 run/item/value 指定，撤销用事件 ID；另提供仅本机访问的可视化网页，复用相同反馈与撤销接口；不安装常驻服务。有效评价按推荐取最新未撤销事件；学习再按视频取最新顺序号，跨轮重复评价不重复计权。相同幂等键同内容返回旧事件，异内容拒绝。撤销追加事件，不删除历史；撤销替换评价恢复此前有效评价。

later 仅内容冷却，不更新兴趣。无原因 useful/not_useful 按正负 1 分摊至最多 5 个排序后标签；无标签不推断主题。只有显式太长／太短才对实际时长桶产生负证据，不从无原因负反馈学习时长。其他原因仅保存，不推断内容难度、信誉或作者黑名单。

每特征按上海日期汇总，日净贡献截断至 ±daily_cap，再按半衰期衰减。激活需同时满足视频数、日期数、净证据绝对值、方向一致性四门槛；一致性=(绝对日贡献之和+绝对净贡献)/(2×绝对日贡献之和)。相反反馈抵消，衰减后不达标则不再激活。权重由净证据映射并截断；最终单视频仍受总调整／位置护栏。

反馈事务先提交，再更新证据及 head；快照／证据／head 在一个事务，失败回退上一有效 head。下次启动自动重算。一次生成固定一个偏好版本，新反馈不影响运行中已加载版本。learning.enabled=false 暂停应用权重，不停止保存／重算。

preferences 可查看、reset 或 restore。恢复／重置固定版本至下一次新反馈或撤销，避免启动立刻覆盖；该诊断模式不继续衰减。新反馈解除固定并按完整历史重算。reset 是清空当前权重，不删除证据历史，日常无需确认规则。

## 8. 维护与兼容

旧入口／参数保留。backup 使用 SQLite 在线备份且拒绝覆盖目标；不提供自动覆盖数据库恢复。import-legacy 显式读取指定目录，默认只导入 preview，明确 --published 且存在正式产物才登记推荐；验证当前上下文、原来源和选择。按目录确定导入 ID，重复导入幂等，不自动升级首次预览导入。旧字段未知使用默认值，原文件不改。

为避免无反馈偏差，preferences 同时显示推荐总数、反馈数、已评价数、反馈覆盖率和已评价有用率；later 不作有用率分母，无反馈不是负反馈。有用率不能代表全部推荐真实质量。

## 9. 验证、限制与未实现项

50 项离线测试覆盖原有 5 项，以及真实 RSS 字段、异常时长、正文保留、多关键词公平去重、别名合并、硬时长与历史过滤、单次／零调用、非法模型输出、探索配额和不足、评分／移动护栏、同日爆量、重复视频、无反馈、later、激活／衰减／抵消／撤销、幂等、偏好更新事务回退、版本恢复、反馈写入失败、文件中断／进程中断恢复、备份、旧导入和 CLI 兼容。

未实现：字幕、下载、转写、扩词、自主检索、黑名单、常驻推送、外网网站部署、观看追踪、独立语义转载去重。没有真实模型端点或 RSS 在线复验；不承诺推荐准确率提升。时长桶是保守学习，只惩罚明确被指出不合适的桶，不推断其他桶必然更好。模型漏选的短名单外内容无法被偏好救回。没有自动清理数据库或文件保留期策略，个人使用量大后可手动归档备份。

没有修改 requirements、现有凭据、RSSHub 部署、用户兴趣配置或相邻项目。


## 本地可视化适配层（2026-10-24）

新增 main_gui.py 和 info_agent/web.py，使用标准库 ThreadingHTTPServer 仅监听 127.0.0.1。静态资源位于 info_agent/web_assets，无额外依赖或前端构建。网页包含简报生成／采集预览、历史、反馈撤销、偏好查看和设置。生成在独立线程运行，每个请求或工作线程单独创建数据库连接；网页只允许一个生成任务，并在运行时拒绝配置修改。写接口检查本机会话令牌与来源；配置采用快照冲突检查和原子保存。原有 CLI、工作流和学习算法不变。新增 11 项网页测试，全套共 61 项通过。详细操作与边界见《可视化界面.md》。
