# 信息筛选助手项目架构书（2026-10-25 Agent 核心实现版）

本文描述当前已实现代码。前端契约见《前端对接约定-动态候选池.md》，新增本地 Python／CLI 查询见《Agent核心接口.md》；多来源和安全诊断继续保留。不扩展为 Agent 任务系统、插件、MCP、观看计划或追课管理。

## 1. 运行链路与模块

采集与生成已经解耦：用户／本地定时器 → collection.collect → RSS 元数据解析 → 按来源贡献事务写入 pool_items；用户生成 → pool.snapshot → 固定本次候选 → 一次逻辑模型短名单 → 严格校验 → 本地有限排序／探索 → 正文和推荐快照原子提交 → 文件导出。

- schemas.py：新旧 Profile 规范化、source_plan、过滤／采集策略及内容模型。
- rss.py / dynamics.py / covers.py：有界获取、视频／动态分别解析、身份与作者证据、文字清理、可信图片。
- sources.py：按来源种类、同类订阅轮流分享候选预算及字段合并。
- filtering.py：Rule 注册表（ID／版本／说明／匹配器），保守抽奖／广告标记与明确 UP 屏蔽。
- pool.py：每来源贡献、时效和当前配置过滤、固定读快照、schema v3 候选回填审计。
- collection.py：有限轮流补采、即时入池、采集记录和安全故障处理，不导入模型工厂。
- jobs.py：SQLite 任务、跨进程互斥与租约、本地服务定时器。
- workflow.py / ranking.py / preferences.py：既有 LangGraph、严格短名单、有界偏好排序与本地学习。
- storage.py / migrations.py / errors.py：SQLite、备份迁移、导出恢复、安全错误码与公开诊断。
- web.py / web_assets：本机 API 与现有前端设计；main.py、main_gui.py 和 CLI 保留。
- agent.py / agent_core.py / agent_models.py / retrieval.py：绑定档案的 typed 查询、检索、证据校验及费用幂等。
- settings_service.py / agent_migrations.py / agent_cli.py：共享设置事务、目标修订审计、v4 迁移和非交互入口。

默认 main.py／网页“生成”只读候选池，不隐式采集。CLI collect、--preview 与网页“刷新来源”只采集，不调用模型。旧 Python build_briefing 接口的默认内部兼容路径保留，现有显式注入测试可继续调用；正式 CLI／网页生成均明确使用 from_pool=True。POST /api/run 保留：真实网页默认 preview=true 映射采集，false 映射池内生成；新前端使用独立接口。

## 2. 三个来源入口

source_plan 是配置权威；旧 sources 只在无 source_plan 时迁移，在返回数据中作为只读兼容投影。旧客户端可提交仅 sources 的 patch，在 API 边界转换；同一次 patch 同时提供两者会被拒绝。新版保存写 schema_version=4，读取旧配置不自动改写文件。

关键词搜索仅使用用户配置的最多 5 个词，不扩展搜索；指定 UP 最多 10 位，每位独立启停并选择 uploads/dynamics/both；我的关注单选 videos/dynamics。UP 动态、关注综合动态的内容类型为 all/video/non_video，未知只进入 all。投稿和关注视频忽略动态类型选项。禁用配置仍保留。

路由为 /bilibili/vsearch/{keyword}/pubdate、/bilibili/user/video/{uid}、/bilibili/user/dynamic/{uid}/directLink=0&hideGoods=0、/bilibili/followings/video/{uid}、/bilibili/followings/dynamic/{uid}/embed=0。登录仍只由用户自建 RSSHub 端负责，不读取／保存 Cookie，不修改部署。不凭 UID 或模糊错误断言登录成功／过期；状态轮询只读缓存。

视频与动态分别解析。动态保存 dynamic_id、类型、实际作者 UID（有证据时）、原作者 UID（有证据时）、发布时间、清理正文、图片及转发说明。只在明确的视频地址／播放器元数据中提取视频身份，不把正文偶然提到的 BV 当作同视频证据。source_ids 继续只负责 AV/BV 身份；sources 负责来源溯源，dynamic_contexts 保留原动态及新增说明。

作者 UID 仅来自条目明确字段、AuthorID 模板或与条目 creator 精确匹配的单作者 RSS 频道身份；不使用请求账号 UID 或昵称猜测。关注频道的账号身份不能替代条目作者。上游未提供原作者 UID 时保持未知，因此针对未知原作者的屏蔽不能保证覆盖。图片不是类型证据；新版未知卡片只在“全部”出现。

## 3. 有界分页

仅 UP 动态支持 offset。每位默认最多 3 批（配置上限也是 3），完成一批后排回队尾，先让其他来源获得请求机会。游标取过滤前最后一条动态 ID，解析器保留原始条目 ID 序列，即使条目后续被规则或类型过滤也不改变游标。

停止原因包括原始批次为空、缺少游标、游标不推进、无新增原始 ID、整批已知发布时间都早于下界、达到每位批次数、全局请求／时间预算或请求失败。混合置顶旧条目与新条目的批次不会仅因最早时间过旧而提前停止。未知时间不伪造精确末尾；没有 has_more，不声称已抓完。请求失败单独记错，不作为到末尾。

投稿和关注综合动态只请求一批，不追加分页参数。默认全局最多 48 请求、120 秒；rss_timeout_seconds 默认 15 秒，单请求再取剩余全局时间的较小值，RSS 响应最多 2 MiB，不增加 RSS 重试。上限集中在 collection 配置（最多 96 请求／600 秒）。有限补采不承诺严格增量或完整历史。

## 4. 持久候选与过滤

pool_items 按 profile_id＋RSSHub 地址的 namespace、来源 kind/key 和原始条目身份保存贡献；同视频的不同来源贡献独立留存，筛选时才按身份合并。这样禁用来源、仅屏蔽动态、关闭规则都可重新计算，不让被排除来源的文本混入独立投稿。collect 每个成功批次先入库，命中只标记不删除；失败批次事务回退，此前成功批次仍在池中。

动态贡献（含关注视频动态）按发布时间起默认 72 小时有效，可选 24／168；关键词视频和 UP 投稿不套用动态 TTL。无效／缺失或明显超前的发布时间回退到首次入池时间，并记录 expiry_basis；未来容忍默认 300 秒。重复抓取不更新首次时间，也不改写同一动态已经保存的发布时间。到期严格退出当前候选，原始条目和历史保留。调整 TTL 按当前设置重算。

filtering.Rule 注册机制包含 ID、版本、开关配置、固定说明和命中原因。lottery v1 默认开，只对动态同时出现参与指令与抽选／奖品承诺作保守标记；讨论、教程、结果和单独“抽奖”不命中。独立 advertisement v1 保留促销动作、购买／领券及真实商家域名链接分支；兼容补丁另识别淘宝闪购／美团／美団的搜／嗖数字密令＋优惠信号、复制／copy 打开手淘下单＋口令＋价格信号。长篇、新闻、技术讨论、分析及否定语境仍保留，品牌名不单独构成命中。lottery v1 补充参与要求＋抽取／抽选＋奖品人数列表，优先读取已保存正文，仍仅对动态生效并保护教程、结果公告与骗局提醒。两规则版本继续为 1，不修改真实开关。新配置默认两规则开启，旧显式规则列表保持不变，网页目录可开启新规则。未知规则／版本保留配置，明确提示未加载，不暗中执行不同版本。

blocked_ups 是用户明确名单，不来自负反馈。dynamics 排除该 UID 作为发布／转发作者的动态贡献；all 还排除该 UID 已被明确识别为原作者的内容。缺乏 UID 不以昵称或采集账号替代。取消屏蔽后，仍在有效期且满足其他条件的条目可恢复。规则和来源变化不改变学习身份。

pool.snapshot 在一个短 SQLite 读事务中固定来源贡献、采集指针及推荐冷却，再应用当前来源、类型、TTL、规则、屏蔽与视频时长约束。非视频时长归一为 null，不按未知视频时长排除。eligible_count 是预算前有效总数，生成时仍按原公平策略取 max_candidates（默认 60、最多 200）。filter_counts 是当前启用来源、未过期且匹配类型的不同内容命中数，不因开关关闭而归零，不等于最终排除数；同视频还有其他未命中贡献时仍可入选。

## 5. 一次筛选、事务与学习

模型只收到固定快照的 ID、标题、清理正文／简介、作者、发布时间、视频时长、标签、内容类型、文字可用标志及文字动态上下文；不传图片／封面，不识图，不获取字幕或下载音视频。无文字图片的摘要由程序约束为缺少文字、建议打开原文，不能编造图片细节。作者主张须归属于作者，不升级为独立核实的事实。

最多一次逻辑模型短名单，预览和无候选零调用。短名单上限 min(候选数,2K+E)，重复 ID、未知 ID、超量、非法字段／分数均失败，不静默删除、不纠错二次调用。SDK 原有网络重试策略不变，HTTP 尝试与逻辑次数分开记录。

常规／探索仍约 80/20：K≥5 时四舍五入 K×exploration_ratio，K<5 不强制；不足不凑。探索不应用学习权重，常规总加减分最多 ±5、短名单内最多移动一位。

反馈“有用／没用／暂时不想看”、可空原因、幂等与撤销保留。没有反馈未知；later 只冷却内容，不推断兴趣。弱证据跨视频／日期、每日限额、衰减、相反抵消与撤销重算不变；明确兴趣优先，无原因负反馈不推断时长或难度，不自动屏蔽作者。默认跨 3 视频／3 日期、每日 ±1、60 天半衰期、净证据 1.5、一致性 .7、5 标签分摊，参数仍在 learning。

旧稳定 context 兼容 profile_id、明确兴趣、时长分桶及 max_tags。v4 开始由明确的目标身份关联兴趣修订：同目标调整使用 legacy_anchor 保留旧 context，切换目标产生新 goal_id/context，撤销恢复原身份；见下节 Agent 核心。来源、关键词、TTL、规则和临时时长不重置学习。v2 审计与备份保留，旧反馈替换／撤销语义不改。

正式正文和推荐快照同一事务提交才进入推荐冷却。模型失败不消耗池中内容。生成期间新入池内容留到下轮。数据库提交后导出失败保留正式状态与“已保存、无需重新生成”提示，recover 幂等重建文件，不重复推荐；采集导出失败不变成正式简报。

## 6. 任务与本地定时器

POST /api/collect 与 /api/generate 独立；collection_job 与 job 分别展示，同类防重复、不同类可并行。所有网页端口和 CLI 共用 SQLite task_leases/task_jobs。BEGIN IMMEDIATE 原子领取，当前活进程持有同类租约时不会因心跳延迟被中途夺取；每 30 秒续租，原进程退出后可恢复。活进程中的异常挂起需重启该本地服务，不冒险重复付费请求。配置保存也在数据库写锁内检查活动任务与完整 expected 快照，保持原子文件替换与冲突拒绝。

本地网页服务存活时运行一个轻量定时线程（默认关闭、间隔 60 分钟），不创建系统任务／外部进程队列。启用或改变间隔后从当前时刻计时，默认间隔可选 30/60/120/360 分钟；SQLite schedule 状态与采集租约共同保证多进程只领取一次。暂停／休眠时不执行；重启后至多处理当前到期的一轮，不追补无限历史轮次。轮询不触发采集。

前端保留现有布局，草稿仍必须手动应用。sources_v2、filter_rules_v1、candidate_pool_v1 与旧能力同时可用。图文显示类型、无视频时长、原文／转发上下文及可信 CDN 图片回退；CSP 保持域名白名单，无任意 URL 代理。

## 8. Agent 核心：独立检索与证据流程（SQLite v4）

实现为 info_agent.agent.AgentCore 与 info_agent.agent_cli，不依赖网页、交互终端、MCP、插件或新部署。宿主构造时绑定可信 root/profile_path 与真实 profile_id，请求不能通过另填档案 ID 访问其他数据。完整类型、参数及示例见 [Agent 核心接口](Agent核心接口.md)。

当前 v3 要求 question 保留原问题，terms 由宿主提供；两检索接口共用去空白、NFKC/casefold 保序去重及 8 词／100 字符限制。query 清理后为空在请求占位前报 QUERY_TERMS_REQUIRED，search 仍能无词浏览。仅显式 time_range 决定日期，question 不推断时间、来源、作者 UID 或类型；默认来源是当前允许来源。个人简报行为不变。

retrieval 共用原 Article、RSS 清理、AV/BV 映射、来源贡献、规则／人工屏蔽和模型工厂。从本档案当前启用的长期来源及保留的临时来源先文字检索，再截取相关候选，不从个人预算截断后的列表中查找。问题查询不应用推荐冷却、学习排名、探索、个人默认时长或动态 72 小时推荐期限，也不写正式推荐、反馈或学习。显式时间、来源、内容类型和查询时长约束仍执行。

按发布时间起点包含／终点不包含，默认 Asia/Shanghai，仅显式 period=today 解析为当天绝对区间，问题文字不推断时间；缺失时间不以采集时间替代。显式中英文关键词匹配与受控 aliases 不从问题拆词、不调用关键词模型、不猜角色作品。跨来源同视频按可靠身份合并，保留转发文字、来源、采集和发布时间。旧版只保存简介时标为文字有限，读取详情不访问原链接。

Agent 查询在读取现有 pool_items/temporary_items 后先逐条应用允许来源、时间、类型、时长及规则，再保留独立 contributions/documents 检索，最后只合并展示身份。merge_article 的最长正文仅为个人简报／展示投影，不能充当查询证据；其个人流程行为不变。文字、链接、作者和发布时间在同一来源贡献内配对，不能从被排除贡献借用命中文字，也不能为缺失时间借另一来源时间。

search_items/get_item 零模型；query_updates 检索后默认最多 30 条、单条 1200 字符／总输入 18000 字符、返回最多 8 条证据／总输出 10000 字符。模型只返回已知 ID、原因和连续原文，严格验证 ID、去重、字段、数量及片段存在于本次输入，元数据由程序回填。无候选／缓存零调用；不追加纠错、不放宽非法结果。证据由宿主组织答案，不冒充事实核查、不推断图片内容。

v3 先结构字段校验和原始 quote+reason 总字符预算，再核对所有 ID 和每条原文／span；全部通过才按 ID 保序保留第一条，之后检查不同 ID 的请求／宿主上限。duplicates_removed 默认 0，缓存保存去重选择和计数，首次、缓存及重放共用同一处理函数；错误重复项不能被隐藏。MODEL_DUPLICATE_IDS 留作历史及个人简报兼容，Agent 有效重复不再触发。提示加强具体相关证据、reason 对核心问题的支持、手机操作正例／会员推广反例及预告／条件／作者主张边界，没有新增模型或语义硬词规则。全局输入预算现在按实际完整提示长度计算，不靠固定提示预留数掩盖增长。

text_evidence.py 按真实检索词组／别名提取多个命中窗口，NFKC/casefold 到原文码点有显式偏移映射。窗口两侧最多 80 字符、随预算缩小，按新词组覆盖、总词组覆盖、稳定来源／字段／偏移排序；所有窗口字符总数受单条预算约束，元数据和兼容 text 也计入全局预算。全局不足逐次减半单条预算重提取，再不足则截断候选。每个窗口单独携带来源和字段，不拼接成连续引文。模型内部可返回 span_id；即使不返回，也只允许在单个已提供窗口内验证 quote。snippet_evidence、quote_evidence 与详情 body_spans 将文字映射回原来源，详情按贡献公平读取并显式分隔。缺失／未展示部分保持截断标记，不声称已阅读全部。

temporary_items 以 namespace/关键词/原条目键保存临时视频搜索，temporary_origins 保存查询来源证据。默认仅已有数据，显式 temporary_keywords 才有界采集（默认 3 词／3 请求／20 秒／60 条，无重试）。临时内容不写长期配置、不进入个人池，后续同档案可复用。转为长期关键词仅提升具有该词搜索来源证据的数据；新词无数据返回等待／刷新提示，不自动启用停用来源。范围明确仅视频。

source_observations 分来源保存检查、最后成功、错误和数量，失败不擦除上次成功；查询附覆盖摘要。found 与覆盖不足可并存，no_match、insufficient_evidence、collection_failed、model_failed 分开；未请求预算不伪造检查，状态读取不请求 RSSHub。

agent_requests 用事务占位、请求摘要、进程身份和私有结果实现跨进程幂等；同编号同参数合并，不同参数拒绝。同步等待有界，当前请求的工作线程不是新部署服务；超时后同编号可等原请求，原进程退出且结果不确定则拒绝自动再次付费。生产查询克隆 SDK 客户端设置剩余超时、输出 token 上限和零重试，个人模型策略不变。

agent_cache 键含档案／当前来源、规范化问题／词、绝对日期、相关内容版本、规则／屏蔽／别名／预算、模型身份及提示版本，命中后重新核对访问范围并回填当前来源时间。指标区分缓存、重放、本次逻辑调用、实际请求、耗时和 token，原费用放 origin_metrics。不保存完整问题、提示、模型原文或供应商原始异常，不公开查询日志。

当前证据／提示版本为 agent-evidence-v3-explicit-terms-dedup，内容版本纳入每个允许贡献，短来源修订不会被最长正文掩盖。旧策略缓存不再命中；旧已完成请求缺失或不匹配策略版本时返回 QUERY_CONTEXT_CHANGED，不自动追加调用。采集时间／查询归属不影响模型输入装箱，返回时重新回填。这次修复仅改读快照、片段与 JSON 溯源，不增加 schema 或迁移，不改真实库及个人推荐策略。

## 9. 目标身份、修订与可撤销设置

SettingsService 同时服务网页和 Agent。Agent 白名单仅 keywords/interests，增量关键词遵守旧约束；网页保留高级设置、expected 快照、任务互斥和本机保护。同 request_id 幂等，version 冲突明确拒绝。
