## 能力与配置契约

GET /api/state 保留原字段，新增能力 sources_v2、filter_rules_v1、candidate_pool_v1。仅完整可用时设 true；候选池能力需涵盖独立采集、池筛选和定时采集。过滤页须 filter_rules_v1 和 candidate_pool_v1 同时可用才实际保存。sources_v1 等旧标志继续保留。

profile 新字段如下（示例值不是实际用户设置）：

```json
{
  "keywords": ["codex"],
  "source_plan": {
    "keyword_search": {"enabled": true},
    "ups": [{"uid":"123","enabled":true,"scope":"both","content_type":"all"}],
    "following": {"uid":"456","enabled":false,"scope":"videos","content_type":"all"}
  },
  "filters": {
    "rules": [{"id":"lottery","enabled":true}],
    "blocked_ups": [{"uid":"789","scope":"dynamics"}]
  },
  "collection": {"enabled":false,"interval_minutes":60,"dynamic_ttl_hours":72}
}
```

- ups 最多10个，不重复 UID；UID 数字字符串1–30位。ups.scope 为 uploads/dynamics/both；following.scope 为 videos/dynamics，单选；content_type 为 all/video/non_video。uploads 和 videos 模式忽略 content_type。
- 未知内容类型仅进入 all，转发以其内容类型判断，不能用“有图片”判为图文。视频动态不等于原创投稿。
- blocked_ups.scope 为 dynamics/all；前者仅排除动态来源的贡献，不应让同视频的独立投稿来源一起消失。全部屏蔽按真实作者 UID 判断，不能用昵称或抓取账号 UID 替代；转发作者与原作者需区分、说明语义。
- 关键词最多5个，至少启用一个有效来源。禁用来源仍保留配置。
- 前端间隔提供30/60/120/360分钟，动态有效期24/72/168小时，默认定时关闭、间隔60、有效期72。保留其他后端高级配置，不隐式开启后台任务。
- 来源保存 POST /api/profile {expected:完整载入时profile,changes:{keywords,source_plan}}。
- 过滤保存同接口 changes:{filters,collection}。expected 乐观并发校验继续有效。
- 旧配置无损迁移为三个入口；source_plan 为新配置权威来源，不允许和旧 sources 双向漂移。CLI 兼容旧输入。来源/规则/临时时长变化不重置兴趣学习。

state.filter_rule_catalog 可返回 [{id,label,description}]。前端按目录生成独立规则开关，并保留未知既有规则的配置。后端采用有版本的规则注册机制，命中记录包含规则 ID、版本、原因。第一版仅 lottery，不扩大为泛化广告判定。统计未提供显示未知，不显示零。

## 独立任务与状态

- POST /api/collect {} 返回采集任务；state.collection_job 为该任务。采集永不调用模型。
- POST /api/generate {} 返回生成任务；state.job 保持现有任务形状。只读池、固定候选快照，不隐式请求 RSS。有效候选为空零模型调用。
- 任务字段 id/status/started/finished/run_id/record_available/error_code/error_message 与现有诊断约定兼容。status 使用 running/completed/failed。采集和生成允许独立运行，各自防重复；状态轮询只读，不触发采集。
- state.pool = {eligible_count,last_collected_at,filter_counts:{lottery:12}}。eligible_count 是按当前生效来源、规则、有效期、冷却和硬约束计算的可用数量，不是原始入库总数；需在文档说明是否应用候选预算。建议返回预算前有效总数，生成时再公平截取。
- 前端有能力时切换“刷新来源”并调用 collect，生成切换 generate；无能力仍用旧 /api/run。
- 更新采集记录、失败记录和历史展示，采集结果不可冒充正式推荐；保留现有 run_id 准确关联和安全错误信息。

## 采集、候选与时效语义

原始条目应先入池，保存来源、原始作者 UID、发布时间、动态 ID、视频 ID（确有证据才映射）、清理正文和图片地址。HTML 清理安全；图片只展示，不发送给视觉模型，不新增字幕处理。纯图片缺乏文字时不能编写具体摘要。

RSS 请求与模型筛选解耦。规则可先标记，但筛选时按当前开关应用，不因命中删除原始条目。解除屏蔽后仍有效的条目可再次参与。多来源按现有公平策略共享候选预算，同视频合并，保留来源；转发有新增说明时保留其有用上下文，不生硬丢掉。

指定 UP 动态路由 /bilibili/user/dynamic/{uid}/{参数串}，部署已验证支持 offset；保持 directLink=0、hideGoods=0，取过滤前最后一条动态 ID。每位最多3批，同时设全局请求/时间上限、发布时间下界；轮流补采，空结果/游标不推进/无新增停止。请求失败不得当作到末尾。当前 RSS 不输出 has_more，不伪造精确末尾判断。

关注综合动态 /bilibili/followings/dynamic/{uid}/embed=0，当前部署无分页，仅一批。投稿视频 /bilibili/user/video/{uid} 当前无翻页。不得添加无效分页参数；不修改 RSSHub 部署。

动态默认发布时间后72小时退出推荐候选，但保留历史去重记录。不要把重复抓取时间当新发布时间重置有效期。缺失/异常发布时间保守处理并记录依据，不能无限续期。视频原有时效策略保持，不能一律套动态72小时。较早池中内容也必须符合当前启用来源。

定时任务只在本地服务存活时工作，重启不补跑无限任务，多服务进程须有跨进程去重/租约，避免每个端口各自采集。模型失败不标已推荐；生成期间新入库内容留到下一轮；正式简报提交后才登记冷却。临时时长只应约束视频，不误杀非视频动态。

## 已实现约定与联调说明（2026-10-25）

sources_v2、filter_rules_v1、candidate_pool_v1 现均为 true，保留三个旧能力。配置与请求字段沿用本文；规则配置补充 version（省略为 1），目录返回 id/version/label/description。仅接受规则 id/version/enabled，不接收 Cookie 或可执行匹配代码。未注册 ID／版本保留配置，并在 state.filter_warnings 提示不执行。source_plan 为权威，旧 sources 是兼容投影；旧客户端单独提交 sources 的 patch 在边界转换，同一 patch 同时提交两种来源格式拒绝。

pool.eligible_count 是当前来源、类型、TTL、规则、明确屏蔽、视频时长及推荐冷却后的预算前总数。生成再应用现有 max_candidates 公平预算。pool.filter_counts 统计当前来源／未过期／符合类型范围内的不同内容命中数，规则关闭后不归零，也不等于最终排除数；有未命中独立贡献的同视频仍可能保留。pool.last_collected_at 表示上次成功完成采集，失败任务另见 collection_job。

采集写 runs.operation=collect、终态 status=collection，任务 status=completed；采集没有推荐／报告正文。生成写 operation=generate，沿用 completed/empty/failed。旧 /api/run 的 preview=true 映射只采集，false 映射只读池生成；新 /api/collect 和 /api/generate 均使用 {}。任务在开始前分配确切 run_id，跨端口可见，错误码／安全详情不退化。source_results 新增 batches、stop_reason；失败补采可以 count>0，表示此前成功批次已保留，不把后续失败当作精确末尾。

stop_reason 为 single_batch、empty_batch、missing_cursor、cursor_not_advanced、no_new_items、time_boundary、batch_limit、global_request_budget、global_time_budget、request_failed。time_boundary 仅在整批已知时间都越过下界时停止，避免置顶旧条目提前截断。没有 has_more，不宣称抓取完整。

Article 向旧字段兼容扩展 content_type（video/text/image/article/audio/live/unknown）、is_dynamic、dynamic_id、author_uid、original_author_uid、images、repost_text、dynamic_contexts、text_available、filter_hits、expiry_basis。images 仅可信 B 站图片 CDN 的内容图路径，不包含头像／表情；不进入模型。未知类型只有 all 可见；原作者缺失不猜测。dynamic_contexts 保留动态原文地址及说明，图文卡片显示无视频时长、原文和图片加载失败回退。无文字图片不生成具体图像摘要。

动态 TTL 按每来源贡献应用，包括关注视频动态；独立关键词视频和 UP 投稿不套用动态 TTL。缺失／异常或明显未来时间采用首次入池回退，重复抓取不续期。仅动态屏蔽只去掉该作者的动态贡献；全部还可排除已证实该 UID 为原作者的贡献，不猜测未知 UID。解除后按当前规则恢复。

采集和生成各自跨进程互斥，可彼此并行。服务内定时器默认关闭，首次启用／改间隔后计时，多个进程由 SQLite 原子领取，不创建系统任务。服务启动确认旧任务进程已退出时，持久化 PROCESS_INTERRUPTED 并保留池；活进程不被租约心跳延迟中途抢占。网页配置保存与两个任务的启动互斥，且仍做完整 expected 冲突检查。

SQLite v3 自动备份、事务建表与候选回填，pool_imports 记录证据归属／跳过；不删除原历史，不以文件推断正式推荐。正式事务提交后导出失败仍显示“简报已保存”，采集导出失败只表示采集资料已保存。当前真实库备份为 workspace/info_agent.sqlite3.pre-pool-6101c284b9.sqlite3。

浏览器隔离验证了旧能力下仅存草稿、新能力下手动应用、每位 UP 停用／范围、关注动态／类型、过滤命中统计、规则切换、仅动态／全部屏蔽与恢复、手动与定时采集、只读池生成、图文回退及反馈撤销。定时测试通过注入时钟推进 31 分钟完成，没有等待真实周期；生成不增加 RSS 请求。生产页只做只读加载，没有触发真实生成或采集。图片回退使用可信 CDN 的无效图片地址，未识别图片。
