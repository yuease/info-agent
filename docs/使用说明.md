# 使用说明（2026-10-25 Agent 查询核心版）

2026-10-26 v3 更新：query 必须提供原 question 和至少一个有效 terms（CLI --term），不再自动拆问题或从“今天／today”推时间；今天需显式 --today。缺词 QUERY_TERMS_REQUIRED 在采集、模型和付费占位前返回。search 无词仍可浏览。结果先校验所有原始条目再保序去重，duplicates_removed 默认 0；任何错误引用仍失败，缓存和重放保留计数。详见 [宿主调用与冻结复验](Agent宿主调用与复验.md)。

新增独立 Python／JSON CLI 查询，默认只读本档案允许的保留内容，完全不依赖网页。接口、预算、错误码与示例见 [Agent 核心接口](Agent核心接口.md)。个人简报仍使用下面原入口。

本次修复 Agent 查询的两种漏报：正文后半段的命中改为带上下文的原文窗口送入模型；同视频的短来源正文不再被更长来源覆盖。搜索、证据和详情增加可选来源／偏移信息，窗口之外的文字仍视为未检查；不同来源不借用链接或时间。个人简报和页面设计不变，无额外数据库迁移。证据策略版本已更新，旧缓存不再命中；旧请求重放若提示 QUERY_CONTEXT_CHANGED，不会自动再次付费，需要明确新查询时才换请求编号。已运行的宿主 Python 进程需重新加载代码，本轮未启动或迁移真实服务。

```powershell
cd D:\notebooks\info-agent
# 以下操作零模型调用；默认不联网
& D:\Anaconda3\envs\agent\python.exe -m info_agent.agent_cli search --term Codex --term 重置 --today
& D:\Anaconda3\envs\agent\python.exe -m info_agent.agent_cli preferences
& D:\Anaconda3\envs\agent\python.exe -m info_agent.agent_cli sources
& D:\Anaconda3\envs\agent\python.exe -m info_agent.agent_cli item ITEM_ID --max-body-chars 2000
# 显式临时视频搜索才联网，不写长期配置或个人简报池
& D:\Anaconda3\envs\agent\python.exe -m info_agent.agent_cli search --term Codex --collect-temporary --request-id temp-001
# 有候选且未缓存时才调用现有模型；同编号重试，勿自动换编号
& D:\Anaconda3\envs\agent\python.exe -m info_agent.agent_cli query '今天有没有 Codex 重置相关消息' --term Codex --term 重置 --today --request-id query-v3-001
# VERSION 从 preferences 读取；CHANGE_ID 从 update 返回读取
& D:\Anaconda3\envs\agent\python.exe -m info_agent.agent_cli update --expected-version VERSION --request-id settings-001 --add-keyword Codex
& D:\Anaconda3\envs\agent\python.exe -m info_agent.agent_cli undo CHANGE_ID
```

问题查询仅按显式时间参数筛选、默认 Asia/Shanghai，显式 period=today 返回具体区间；问题中的“今天”不会触发时间过滤，缺失发布时间单独说明。历史查询不受动态推荐 72 小时或个人冷却影响，但仍受当前来源、抽奖／广告规则和人工 UP 屏蔽约束。结果可能存在但覆盖不足，请同时查看 coverage，不能把保留池的无匹配当成全网无更新。纯图片不识别；query 只选原文证据，由宿主组织最终回答。

长期关键词增删是增量修改，仍最多 5 词，不自动启用停用来源，也不等于立即取得数据。返回 needs_collection/data_ready/next_action。相同临时搜索词已有来源证据时仅复用相应数据。临时搜索只覆盖视频，默认不进入个人简报，后续同档案可复用。无结果绝不隐式联网。

网页兴趣设置新增“调整同一目标／切换目标”：前者延续学习与旧反馈权限，后者隔离旧目标；Python／CLI 改兴趣必须传 interest_mode。长期设置撤销用 change_id，只恢复原关键词／兴趣字段，不覆盖后续无关修改，同字段有后续变化明确冲突。普通查询不会修改兴趣、反馈或学习。

新错误排查：SETTINGS_CONFLICT 先重新读版本；PREFERENCE_UNDO_CONFLICT 表示同字段后续修改，先处理较新的变更；SETTINGS_IO 表示保存待恢复，同编号重试或重新读取，不能换编号重复修改；SETTINGS_RECOVERY_CONFLICT 不会覆盖外部文件。QUERY_TIMEOUT 用同编号重试；QUERY_OUTCOME_UNKNOWN 表示原进程退出、是否已付费无法确认，不自动重发。MODEL_QUOTE_MISMATCH 是原文证据不符，MODEL_OUTPUT_BUDGET 是超量／超长，均不追加纠错模型。CORE_STORAGE_FAILED 检查本地存储后保留编号重试，未知异常只返回安全说明。

首次新版打开旧库前自动创建 pre-agent 备份并迁移至 v4；旧历史、反馈和学习原义保留，未知目标归属不混合。本轮仅临时库／注入来源与模型／固定时钟及隔离浏览器验证，没有真实 RSS、真实模型或真实设置修改。源码更新需关闭并重启原 main_gui.py／info_agent.web 进程，再刷新原端口（默认 http://127.0.0.1:8765），RSSHub 和转发无需重启。下文标注较早阶段的端口和在线验收是历史记录，不表示本轮重新验收。

当前流程：先用 --preview／collect／“刷新来源”采集入池，再运行 main.py／“生成新简报”只读池筛选。采集与生成不会互相隐式触发；详见末尾“动态候选池：当前操作方式”。

## 生成与配置

在项目目录使用 `D:\Anaconda3\envs\agent\python.exe`，或激活现有 agent 环境。保留 `python main.py`（编辑器点击运行）、`python -m info_agent`、`--preview`、`--show` 和 `--profile PATH`。全局参数放在子命令前，例如 `python -m info_agent --profile mine.json feedback`。

默认兼容旧配置的关键词搜索、UP 投稿和关注视频动态；新版请使用 source_plan 配置三入口与动态范围。在网页“订阅来源”中启用并保存，或配置 profile.source_plan（旧 profile.sources 仅兼容输入，见配置示例）。搜索最多 5 个关键词、UP 最多 10 个 UID、关注账号 1 个；UID 必须为 1–30 位数字字符串。关闭搜索允许 keywords=[]，至少启用一种有效来源。推荐上限 1–10，三类来源共用候选预算默认 60，不扩展检索。完整参数见根目录 `briefing_profile.example.json`；未知配置项会报错。旧四字段配置继续可用，不自动改写用户配置。

推荐使用标题、清理后简介、作者、发布时间、RSS 时长及标签。模板头部的 Length、AuthorID、Play、Favorite、Danmaku、Comment 与尾部 Match By、播放器嵌入不作为正文。普通正文中的评论、收藏等词保留。MM:SS 可超过 59 分钟，HH:MM:SS 的秒和分钟必须小于 60。异常或缺失时长为 null。设置 `max_duration_seconds` 后未知或超长内容都被排除；未设置则允许未知时长。

来源种类及同类订阅公平共享候选预算；UP 投稿不依赖关键词。UP 动态每位最多 3 批，其他路由一批；默认全局 48 请求／120 秒，RSS 单请求超时默认 15 秒、最多 40 秒并受剩余总时间限制，响应最多 2 MiB，不重试 RSS。默认正式推荐冷却 14 天；“已推荐”不表示“已观看”。预览、失败运行和未入选候选不占推荐冷却。稳定档案由 profile_id、明确目标身份及特征解释规则（时长分桶、标签归因上限）识别，旧格式身份精确兼容。关键词、UP、关注账号、临时时长及同目标兴趣修订不清空学习或禁止旧反馈；明确切换目标或特征解释规则改变则隔离。旧记录保留，不静默混合不同目标。

## 反馈

`python -m info_agent feedback` 列出当前上下文最近正式简报，交互输入条目编号、评价和可空原因。指定旧简报用 `--run RUN_ID`。非交互命令：

```powershell
python -m info_agent feedback --run RUN_ID --item 2 --value useful
python -m info_agent feedback --run RUN_ID --item 2 --value not_useful --reason 太长
python -m info_agent feedback --run RUN_ID --item 2 --value later --key unique-request-id
python -m info_agent feedback --undo EVENT_ID
```

返回事件 ID；撤销也会记录事件。重复评价只保留当前有效评价，撤销最新评价可恢复此前评价；重复撤销不会增加贡献。幂等键复用同一内容返回同一事件，改内容则报错。反馈写入失败不会显示成功；学习更新失败不撤销已保存反馈，继续使用旧偏好，下次启动自动重算。

“暂时不想看”只设置该内容默认 3 天冷却，不产生兴趣证据。无反馈视为未知，不区分用户是否看完。无原因“有用／没用”只形成标签弱证据，最多分摊到 5 个规范化标签。无原因负反馈不推断时长；明确“太长／太短”（或 `too_long/too_short`）仅对实际时长分桶产生负证据。其他原因仅保存，缺乏可靠属性时不泛化到标签或难度，更不形成作者规则。

学习自动在反馈后和下轮推荐前以本地 Python 计算，无确认弹窗、无模型调用。每视频只取最新有效评价；每特征每日先汇总再限于 ±1（上海自然日），每日净贡献按默认 60 天半衰期衰减。至少 3 视频、3 日期、衰减后净证据绝对值 ≥1.5 且同方向占比 ≥70% 才激活。相反反馈抵消，撤销重算。参数集中在 learning 配置中。

常规视频总加减分不超过 ±5，短名单常规基础排序最多移动一位；不是每个标签分别加 5。探索位不使用自动学习权重。模型先依据明确兴趣建立候选资格，学习只能影响其短名单内部；不能把不符合明确兴趣的内容加入名单。

## 探索

K≥5 时探索目标是四舍五入 K×exploration_ratio，默认 20%；K<5 不强制探索。程序先保留合格探索条目，再补常规条目；探索依基础分，分数相同时考虑与列表的标签／作者差异。探索不足用常规补位，均不足则少推荐。探索范围仍是同一候选池，实际数量在 run.json 记录。

模型未知 ID、重复 ID、超限、非法分数、虚构来源字段或结构错误使本轮失败；不增加模型纠错循环。来源始终取原始候选。正式零推荐生成说明，不产生反馈对象。

## 数据、维护与恢复

数据库是事实来源。每批采集后立即事务保存来源贡献，生成时固定候选快照，模型失败仍保留排查资料；`run.json` 保存配置、准备后候选、短名单、最终排序、偏好版本、计数、失败阶段、耗时、token 与 HTTP 重试指标。采集运行的 `candidates.json` 保存本次去重采集全集；生成运行保存本轮固定的模型候选快照。未入选、被过滤与被预算截取的原始来源贡献仍保留在 SQLite 候选池。token 未提供时为 null；强制中断时未能记录的网络指标也为 null。

正式简报正文和推荐快照在同一数据库事务提交，随后以临时文件加原子替换导出。导出失败可能已提交正式推荐，错误信息不能当作“没有推荐历史”；运行 `python -m info_agent recover` 从数据库重建文件。生成前也会自动恢复已提交文件；网页服务启动恢复已确认中断的任务状态。恢复可重复执行，不重复登记推荐。已退出进程遗留 started/collected 运行标为中断失败，不补登记推荐；活跃进程运行不改动。

```powershell
python -m info_agent preferences
python -m info_agent preferences --restore 12
python -m info_agent preferences --reset
python -m info_agent backup D:\notebooks\info-agent\workspace\backup-20261024.sqlite3
python -m info_agent import-legacy workspace\briefings\OLD_RUN
python -m info_agent import-legacy workspace\briefings\OLD_RUN --published
```

preferences 显示版本、权重、反馈覆盖率和已评价条目的有用率。无反馈不记为没用；选择性反馈使有用率不代表总体准确率。restore 只能恢复当前上下文的旧版本；reset 创建空版本。恢复／重置版本保持到下一次新反馈或撤销，然后重新按完整有效历史学习（reset 不删除历史）。暂停应用学习可设置 `learning.enabled=false`；继续记录和计算证据，但排序不使用权重。

backup 使用 SQLite 在线备份，不覆盖已有目标。恢复数据库备份需先结束使用项目的进程，再手动替换数据库并处理对应 WAL 文件；本版不提供自动覆盖数据库命令。

旧 JSON 不会自动进入历史。import-legacy 默认导入预览，只有显式 `--published`、原运行不是预览且具有简报文件，才登记正式历史；上下文必须匹配，来源及选择须校验通过。重复导入同目录幂等，首次按预览导入后不会因再次加参数升级为正式。缺失字段使用模型默认未知值，不猜测时长或标签。旧运行目录名包含时间时使用上海时间，否则使用导入时刻。旧文件保持原样，新导出在 legacy-* 目录。

## 限制

没有观看状态、语义级转载去重、自动关键词扩展、字幕获取、音视频下载、语音转写、自动黑名单、外网部署或系统定时任务；只有用户明确 UP 屏蔽和网页服务存活时的可选定时采集。AV/BV 只有在 RSS 播放器给出对应关系或数据库已有映射时合并，不额外查询转换。上游模板变体不保证全部识别，需检查候选；不会全局删除正文中的普通词语。偏好仅改变短名单内部排序，无法补救模型漏选。恢复后固定版本暂停衰减直至下一次反馈，属于人工排查模式；正常模式每次启动重算衰减。

## 来源登录与封面

UP 投稿使用 /bilibili/user/video/{uid}；UP 动态、关注综合动态路由及有限补采见末尾；关注视频使用 /bilibili/followings/video/{uid}。登录只由自建 RSSHub 端负责；网页不接收 Cookie、密码，不提供登录自动化。填写 UID 后状态为“尚未检查”，直到一次实际采集提供证据。/api/state 只读最近状态缓存，不因页面轮询反复请求 RSSHub。ready 代表最近一次成功，需结合 last_checked 理解；不能保证当前永远在线。

来源结果分别显示成功、成功但空、需要登录、登录过期或一般来源失败。模糊网络错误不能证明账号过期，会按一般失败处理。部分失败继续其他来源；全部失败和过滤后无候选分别记录，预览都不会调用模型。

封面只从 RSS 已有视频图片或明确 thumbnail/enclosure 提取，拒绝外域和头像／表情等图片。浏览器直接请求可信 hdslb.com/biliimg.com CDN，设置 no-referrer 和懒加载；图片失败或旧记录缺失显示占位。封面不参与模型筛选，也没有通用图片代理。

## 升级与稳定兴趣迁移

升级前关闭旧版网页服务，再重新运行 main_gui.py（已有旧端口被占用时可用 --port 8767）。本轮新版已重启于 http://127.0.0.1:8767；旧 8766 进程已关闭。以后源码更新仍需重启 Python 服务并刷新网页。

旧 SQLite 首次打开会先自动备份到同目录的 *.pre-stable-*.sqlite3，再执行 schema v2 迁移。原运行配置 JSON 和反馈不删除、不覆盖；context_migrations 记录原身份、新归属或无法确认的原因。相同明确兴趣和特征解释规则的旧运行归并后，从有效反馈重算，不相加旧权重。不同目标、不同规则分别归属，无法确认的记录保留隔离。迁移可重复执行，失败事务回退；偏好更新失败可下次重试。

旧权重版本保留审计，不能直接恢复成新档案的偏好；迁移后新生成的版本仍可用 preferences --restore。reset 只清空当前权重，不删除反馈历史。原有导入、备份、撤销、recover 命令继续兼容。


## 错误排查（2026-10-25）

先打开本次任务的“查看失败记录”，核对运行编号。来源提示与筛选提示分别显示：例如 UP 投稿超时、关键词采集成功时，关键词候选仍会进入后续处理；筛选结果又返回重复 ID 时，会另外显示“模型结果校验未通过：返回了重复条目”。不要因为一个来源失败就同时修改 RSSHub 与模型配置。成功但无更新、冷却／时长过滤后无候选、全部来源失败有不同说明，预览和无候选均不调用模型。

运行详情和 workspace/briefings/<运行编号>/run.json 保留 failed_stage、error_type，并新增 error_code、error_message、可选 error_details。来源 source_results 保留 kind/key/label/status/count，并为失败来源补充同样的安全错误码与说明。安全详情中 actual_count/allowed_count 表示实际／允许短名单数，duplicate_count 表示重复的额外次数，unknown_id_count 表示不同未知 ID 的数量；不记录这些非法 ID。字段校验仅展示字段路径和错误类型，额外字段名用 <unknown_field> 占位。

- SOURCE_CONNECTION / SOURCE_TIMEOUT：检查本机转发与网络，或稍后重试该来源；超时不能证明登录过期。
- SOURCE_HTTP：查看安全详情中的 HTTP 状态码并检查来源服务。普通 401/403/503 不自动解释为 Cookie 缺失、过期或风控。
- SOURCE_NOT_RSS / SOURCE_PARSE：检查路由和 RSS 格式。SOURCE_AUTH_REQUIRED / SOURCE_AUTH_EXPIRED 只来自已识别的 RSSHub 明确账号登录诊断，登录仍在 RSSHub 端处理，网页不接收 Cookie。
- MODEL_CONFIG_MISSING / MODEL_CONFIG_INVALID：检查现有模型连接配置。MODEL_AUTH 对应 SDK 的鉴权错误或明确 HTTP 401；MODEL_PERMISSION 对应 403，不能进一步断言风控。MODEL_RATE_LIMIT 对应 429，等待后重试或检查额度。
- MODEL_CONNECTION / MODEL_TIMEOUT / MODEL_SERVER / MODEL_HTTP：候选保留，检查模型端点、网络或服务状态。不会自动增加请求、纠错循环或付费调用；既有 SDK 网络重试策略不变，HTTP 尝试与逻辑筛选次数分别保留。
- MODEL_PARSE：结构化输出无法解析；若异常链有明确 JSON 语法错误，安全详情提供 invalid_json 和行列，否则标明结构不可读或缺少 parsed。MODEL_FIELDS 是字段校验失败。MODEL_DUPLICATE_IDS / MODEL_UNKNOWN_IDS / MODEL_SHORTLIST_LIMIT 是严格短名单校验失败；本轮未登记正式推荐，不会静默丢弃非法条目。
- PERSISTENCE_FAILED：未确认保存时先检查磁盘、目录权限与数据库占用，再查看本次记录；如果页面明确说明简报已保存，不要重复生成。EXPORT_FAILED 且 briefing_saved=true 时，正文和推荐快照已在数据库，可直接网页阅读或下载，运行 `python -m info_agent recover` 重建文件。正式状态保持 completed/empty；预览导出失败没有正式推荐。恢复成功后 export_failed=false、export_recovered=true，保留错误码供审计。RECOVERY_FAILED 表示启动时恢复旧文件失败，本轮尚未采集或调用模型。
- SOURCE_UNKNOWN / MODEL_UNKNOWN / UNCLASSIFIED：证据不足，保守归类，结合阶段、类型及安全计数排查；不按异常文本猜测鉴权或风控。PROCESS_INTERRUPTED 表示已确认原运行进程退出，沿用既有中断恢复逻辑。
