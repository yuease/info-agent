# 前端对接约定：面向人的多来源信息简报

日期：2026-10-24。状态：本轮后端已实现并与现有前端联调。能力标志代表后端功能，不保证具体 RSSHub 账号或路由当前在线。

## 产品范围

本文保留多来源与封面阶段的网页契约，后续动态范围以《前端对接约定-动态候选池.md》为准。当前已另提供 Agent 本地 Python／CLI 查询核心，见《Agent核心接口.md》，没有新增网页 Agent 路由、插件或 MCP。个人简报仍沿用一次模型筛选、常规／探索、反馈和 Markdown，不做追课、观看计划、字幕、热度评分或外部事实核查。

## 1. GET /api/state

保留现有所有字段，新增可选 capabilities：

```json
{
  "capabilities": {
    "sources_v1": true,
    "cover_images_v1": true,
    "stable_preferences_v1": true
  }
}
```

只有功能真正完成并可验证后才返回 true。缺失视为 false。旧后端仍能使用：原关键词设置保留，UP／关注显示“等待接入”，来源页面只保存 localStorage 草稿，不把新字段提交给旧 schema。

`sources_v1` 就绪时，来源表单才会通过现有 POST /api/profile 写入实际配置；按钮变为“保存并启用来源”。草稿绝不自动启用，用户可以明确保存或恢复已生效设置。浏览器存储 key 为 `info-agent.sources-draft.v1.<profile_id>`，只含关键词和 UID，不含 Cookie。

`stable_preferences_v1` 就绪时，兴趣设置与偏好页会说明切换关键词／来源不重置长期学习；否则保留旧行为说明。

## 2. profile.sources

关键词继续使用已有顶层 keywords，新增 sources 结构：

```json
{
  "keywords": ["LangGraph", "Cursor"],
  "sources": {
    "keyword_search": {"enabled": true},
    "up_uploads": {"enabled": false, "uids": []},
    "following_videos": {"enabled": false, "uid": ""}
  }
}
```

旧配置缺失 sources 时，按仅开启关键词搜索迁移。

校验：关键词最多 5 个；启用搜索时至少 1 个；指定 UP 最多 10 个，启用时至少 1 个；UID 为 1–30 位数字字符串，去空白、去重；关注动态启用时 UID 必填；至少启用一种来源。不对 UID 作 JavaScript Number 转换，避免大整数精度问题。

关闭关键词搜索时允许 keywords=[]，但可以保留未启用的关键词方便切换。关闭其他来源也可保留其参数。来源种类只允许上述枚举，不接受任意 URL。

POST /api/profile 仍使用 `{expected: 完整配置快照, changes: {...}}`。扩展允许更新字段 sources，保留原子写入、冲突检查、运行期间拒绝修改，以及高级参数和模型配置不被覆盖的行为。来源表单仅提交 keywords/sources；兴趣表单在 sources_v1 下保留既有 keywords，不再显示重复输入。

## 3. 登录与来源状态

前端不提供 Cookie 输入、登录自动化、Cookie 上传或密钥显示。用户 UID 对应自建 RSSHub 的登录配置。后端不能仅因填写 UID 就认定登录成功；不能从本机环境猜测远端 Cookie 是否配置。

`GET /api/state` 可新增：

```json
{
  "source_status": [
    {"kind":"following_videos","key":"123456","status":"unknown"}
  ]
}
```

kind 当前为 following_videos，key 为 UID 字符串。支持状态：unknown、configured、ready、missing_credentials、auth_expired、error、disabled。

ready 必须来自真实成功记录；configured 也须有实际配置证据；无法判断时用 unknown。可额外返回 last_checked 等非敏感信息。读取 /api/state 不应每次请求 RSSHub：使用最近采集结果更新状态。用户编辑 UID 后，未匹配到同一 UID 的状态显示“尚未检查”。错误信息不能含 Cookie 或原始异常全文。

## 4. 封面与来源溯源

候选与推荐快照中的 article 增加可选字段：

```json
{
  "cover_url": "https://i0.hdslb.com/bfs/archive/example.jpg",
  "sources": [
    {"kind":"keyword_search","key":"LangGraph","label":"关键词 · LangGraph"},
    {"kind":"up_uploads","key":"123456","label":"UP 投稿 · 作者名"}
  ]
}
```

这里 URL 是结构示例，不是可用图片。sources 是来源溯源，不要覆盖现有用于 AV/BV 身份映射的 source_ids。同一视频多个来源命中时合并 sources，优先保留非空合法封面和字段。

封面从 RSS 已有 description 图片或其他明确封面字段提取，先提取再清理 HTML。优先视频封面而非头像或表情，不额外抓视频页面。封面不传给筛选模型，也不进入可信度评分。

前端接受以下 cover_url：HTTPS 的 hdslb.com 或 biliimg.com 子域图片；或同源 `/api/covers/` 下的地址。不接受任意外域、data、javascript、file。原始 HTTP B 站 CDN 图片可在后端对已验证的 CDN 域名升级为 HTTPS。

当前 web.py 的 CSP 只允许同源/data 图片，后端接入必须同步精确放行所用 B 站图片域；不要取消 CSP 或放行全部网络资源。前端已设置 loading=lazy、referrerpolicy=no-referrer、decode=async，以及空字段／加载失败占位。

优先直接加载 CDN。若真实验证显示需要本地代理或缓存，必须对目标主机、重定向、大小、类型及超时做限制，不实现通用 URL 代理。旧记录无封面正常占位，不为了补封面调用模型或重做全部历史。

## 5. 多来源采集状态

`GET /api/runs/{id}` 保留 failures 字符串数组和现有字段，可新增：

```json
{
  "source_results": [
    {"kind":"up_uploads","key":"123456","label":"UP 投稿 · 作者名","status":"ok","count":8},
    {"kind":"following_videos","key":"456789","label":"关注视频动态","status":"auth_expired","count":0}
  ]
}
```

状态为 ok、empty、failed、auth_required、auth_expired。count 定义为该来源成功解析后、跨来源去重前的有效视频数。失败 count=0 不表示没有更新，前端同时显示失败状态。来源成功但空结果用 empty。部分失败继续处理其他来源，全失败不调用模型。

state.runs 的条目可新增 source_labels 字符串数组供历史列表显示。缺失时前端回退 keywords。

## 6. 稳定学习身份

切换关键词、UP 或关注来源，以及临时观看时长，不应改变所属兴趣档案。来源与学习身份需要解耦；profile_id 可作为稳定档案标识，学习特征/策略版本单独管理。

旧 context 数据不能直接删掉或把权重相加。从有效反馈重建证据，保留撤销、替换、按视频去重与每日上限；对明确不同学习目标或时长分桶策略的旧证据保守处理，记录迁移去向。至少保证同一明确兴趣下仅关键词不同的旧反馈可延续。迁移前备份，幂等执行；不能仅修改 UI 文案来假装数据已合并。

现有 current_context 兼容字段可保留，但应基于新稳定档案与已明确迁移的归属判断反馈是否可写，不能再因换搜索词禁止反馈。原始运行 profile 快照不改写。新 UI 不提供 Agent 任务/多用户账户功能。

## 8. 实际实现补充

- GET state 现返回三个能力标志 true、完整 profile.sources、source_status；轮询不访问 RSSHub。
- GET detail 返回 source_results 和候选／快照 cover_url、sources；历史列表返回 source_labels。旧记录未知字段按默认空值占位。
- source_results 的 count 是解析后、跨源去重前数量。empty_reason 新增 all_sources_failed/sources_empty/filtered_empty，前端据此区别错误与成功空结果。
- 认证状态只采用明确上游诊断；缺少凭据用 auth_required → missing_credentials，已过期用 auth_expired，一般超时／403／格式异常用 failed → error。成功空结果也可证明该次请求成功。状态按 RSSHub URL+kind+UID 缓存，last_checked 标明观测时间；没有配置证据不返回 configured。
- 默认每个订阅一次请求，无 RSS 应用重试，最多 16 请求；默认超时 15 秒（配置最多 40），全局候选预算默认 60。先按来源种类、再按同类订阅轮流取样。
- 稳定档案使用 profile_id+明确兴趣文本+时长桶+标签归因规则，采集配置／临时时长不在身份中。明确兴趣文本变化保守视为不同目标；不做语义判断或自动混合。
- 旧数据库先备份，再逐运行审计归属并从有效反馈重算，原 profile JSON 不改写。网页反馈权限、终端权限、统计、偏好及冷却均使用新归属。
- CSP 精确放行两个可信 CDN 后缀的 HTTPS 子域；浏览器直连通过，未实现 /api/covers 代理。旧前端保留该地址格式兼容，但本后端不会生成这种地址。

验收范围：真实关键词 codex 返回 20 条、封面 20 个、模型 0 次。浏览器多来源、UP-only、登录过期与反馈采用隔离数据／注入来源；成功图片使用真实 RSS CDN，另用隔离失效 URL 验证占位。没有已配置 UP UID、关注 UID，未验证真实 UP 投稿或账号关注抓取；不读取现有凭据，不声称账号已登录。


## 9. 安全错误诊断（2026-10-25，兼容扩展）

运行详情及 state.runs 错误摘要增加 error_code、error_message、可选 error_details，failed_stage/error_type 保留。source_results 失败项增加同样的安全诊断字段，原 status/count 语义不变。前端仅展示服务端说明，不根据异常类名或关键词补造原因；部分来源失败与运行失败是两个独立维度。

state.job 和 POST /api/run 响应从任务开始即具有 run_id。工作流失败后仍为这个确切编号，job.record_available 表示该记录是否可读；错误详情按钮以 run_id 打开。job.error 保留兼容，同时提供 error_code/error_message/error_details。数据库正式提交后若导出失败，job.status=completed、job.warning 为安全说明，briefing_saved=true；详情 status 保持 completed/empty 且 export_failed=true。恢复后详情 export_failed=false、export_recovered=true。下载接口仍可从数据库读取正文。

安全详情仅允许数值 actual_count、allowed_count、unknown_id_count、duplicate_count、http_status、line、column，有限 parse_reason 和 validation_errors[{path,type}]。不得包含非法 ID、供应商异常全文或 Pydantic 输入／context。字段路径中未知字段名显示 <unknown_field>。无详细诊断的旧失败记录返回 LEGACY_UNKNOWN 及“旧记录未保存详细原因”，不能按 ValueError 推断解析或身份校验失败。

错误码与排查方法见使用说明“错误排查”；没有新增诊断 capability、配置字段或模型调用。来源能力标志、登录状态缓存、CSRF、本机限制、配置快照冲突和运行期间禁改保持原样。

本次诊断升级最终回归：150 项通过（原 108 项 + 新增 42 项）。新增测试使用注入模型／来源、固定时钟及临时 SQLite，包含敏感异常不进入接口、导出或日志的检查。没有真实模型付费调用或真实推荐／反馈写入。
